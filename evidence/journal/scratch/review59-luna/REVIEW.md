## Findings (ranked)

1. **P1 — `part59/run59.sh:24-32,48-58`: `RETURN_READY` does not mean the phases succeeded.** `run_phase` records a nonzero exit in `run_status` but returns success, and the archive block prints `RETURN_READY` whenever `tar` succeeds without checking `run_status`. If a model fails to load or a 59A/59B phase errors, the script still archives whatever is present and emits the runbook's completion marker; the final exit code is nonzero, but an unattended operator may already treat the tarball as complete. **Smallest fix:** gate the marker on all setup, prefetch, and phase statuses being zero; still make the archive available as an explicitly incomplete artifact when a phase fails.

2. **P1 — `part59/blind_setting.py:86-103,168-192`: partial and stale 59A files can be scored as a complete experiment.** `answers()` globs every `clamp-*.json`; `submit` only rejects an empty list. It never checks the 59A manifest's status, expected steps, or sample counts. A stopped run with some output files can therefore be submitted, and `collect` prints a table with smaller `n` values after calibration passes. Also, a forced run with changed prompts writes new question-hash paths but leaves old files in the directory, so the same glob mixes both runs. **Smallest fix:** validate complete manifests, read only their listed paths, and refuse submission unless all expected prompt/dose/condition cells have eight answers (96 per aggregated table cell).

3. **P2 — `part59/run59a.py:162-178` and `part59/run59b.py:286-303`: hard kills leave permanent lock files.** The `O_CREAT|O_EXCL` lock is removed only in `finally`. `SIGTERM`/`SIGKILL` or host preemption skips cleanup, so the documented resume attempt fails immediately with “another … run holds the output lock,” even when the recorded PID is gone. The interruption test at `test_part59.py:199-244` injects a Python exception and does not cover process death. **Smallest fix:** use an OS-held advisory lock that releases on process exit, or validate and remove a stale PID lock before refusing the resume.

4. **P3 — `part59/run59a.py:201-207`: output granularity differs from the builder brief.** The runner creates one result per prompt and dose (60 files per model), rather than one result per model and dose. Keeping each prompt in its own Part 54-shaped file is readable by `blind_origin.answers()` and preserves all answers, so this does not change prediction scores, but the artifact contract and counts should be stated consistently. **Smallest fix:** update the contract/runbook to specify 12 files per model-dose, or aggregate prompts under an explicitly supported schema.
