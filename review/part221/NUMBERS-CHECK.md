## 3. Numbers the files cannot support

1. **C97 — concept-unit layers.** From `results/part92/step2/neurons.json`, concept units sit at layers
   {2: p92-29; 3: p92-00, -11, -39; 4: -01, -08, -30, -45, -48; 5: -15, -38, -41; 6: -40, -43; 7: -52; 10: -28, -51;
   12: -49} and slot units at {1, 2, 3, 4, 5, 6, 9, 12}. Shared layers: 2, 3, 4, 5, 6, 12 — **15 of 18 concept units**.
   Four concept units (p92-29; p92-00, -11, -39) even sit inside the transplanted band (layers 2-3). The Limits
   sentence "The concept units sit at other layers than the slot units, so they control for personas in general, not for
   early disruption at the slot units' depth" is therefore not supported by the files. The concept counts themselves
   are correct (17/18 in R0, 14-17/18 in the runs); it is the stated rationale that fails.
2. **C84 — "every label row records its cap."** True of this part's 12 Haiku label files (all rows 500 or 4000), but
   the R0 and R1 rows actually used in the scoring are Part 219's, and all 258 read rows in each of
   `results/part219/labels-R0.jsonl`, `labels-R1.jsonl`, `labels2-R0.jsonl`, `labels2-R1.jsonl` carry
   `max_tokens: null`. So "every label row" is false for the labels behind two of the eight table rows.

Everything else the README states as a number is in the files and recomputes to the stated value. Nothing in the README
requires a file that is missing: `PILOT.json`, `manifest.json`, `launch.jsonl`, `replay-R0.json`, `fig221.png`,
`part221/{run221,score221,fig221,test_part221}.py` and every `R*.meta.json` exist.

## FINDINGS

1. **Reproduction is clean.** The scorer regenerates `SCORECARD.md` byte for byte and `scorecard.json` byte for byte
   once the out-of-tree path strings are normalised. My independent recomputation (own label loader, own relative-show,
   own McNemar, own split from `neurons.json`) agrees with every numeric field of the scorecard: 0 mismatches across
   run counts, upstream/downstream/all-21 nets, lost/gained lists, McNemar p, R11-R12 overlap, Part 219's R8 net,
   coupling maxima, norm-ratio range and DeepSeek/two-pass counts.
2. **The headline claim is arithmetically exact.** R11 and R1 have identical 16-upstream nets (11, 11), identical lost
   lists, identical slot-persona counts (4/21) and identical all-21 nets (16). "Removes as many slot personas as putting
   back all 64" is supported; R11's 4/21 equals R1's on the nose, not merely approximately.
3. **The failed prediction is failed for the right reason.** R11 vs R12 discordant pairs are 1 vs 6 (p = 0.125); the
   direction favours R11 but not at α = 0.05. The README reports this honestly and does not inflate it, and its
   headline sentence ("removed R11's count within the test's resolution") matches the scorer's own headline rule text.
4. **The 18-row 4,000-cap count is right but only when both passes are pooled** (9 in pass 1, 9 in pass 2). A reader who
   counted one pass would get 9. The README's wording ("across the six runs") is compatible with 18.
5. **One abridged quotation.** The 221.3 row is labelled "registered text" but drops the registered clause "where a
   unit 'shows' in a run if its pushed answer shows the persona and that run's own unpushed answer does not
   (`score219.py`'s indicator)" and compresses the discordant-pair clause. Not a number error; a fidelity nit in a
   table that says "registered text".
6. **Minor display artifact (scorecard, not README).** `SCORECARD.md`'s runs table prints R13 as `0/21 | 0/21 | 0/18`
   with "not labelled". The README's "identical to R1 token for token" is the correct reading; the zeros are the
   unlabelled-run default, not a measurement. Anyone skimming the scorecard could misread R13 as a catastrophic run.
7. **The R11 two-pass gate sits exactly on its floor** (40 of 42 agree; bar is ≥ 40). It passes, but with no margin.
   Worth knowing if anyone re-runs the reader.
8. **No unregistered number appears to have been introduced.** The figures in the README that are not in the scorecard
   (R8's 4 heads, the 60/64 head counts, the 26-item sample, the 18 capped rows, the 474-row reproduction) are all in
   the metas/manifest/label files.
