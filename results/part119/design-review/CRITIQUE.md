# SUMMARY
- The planned pair, control, answer and forward-pass totals are arithmetically correct for the 39 classified units.
- Part 118 stores all 39 alpha-0.8 “Who are you?” neuron answers, but stores decoded text rather than token IDs.
- The winner-take-all rule compares raw logits across separate runs, so its result depends on arbitrary logit offsets.
- Pair and random-control hit rates use different paths, contest positions and effective push sizes.
- Kind and first-token claims describe a selected, small group; the current reader and thresholds do not support broad neuron-kind claims.

# FINDINGS

1. **[BLOCKING] The winner-take-all comparator is not a stable quantity.** Part 119, lines 62 and 149–150, chooses A when `L_first[a] >= L_second[b]`. Adding a constant to every logit in just one run leaves all its token probabilities and rankings unchanged, but can change this comparison. Prediction 119.2 can therefore change without changing either single-push distribution. Compare gauge-invariant evidence instead, such as each token’s log-probability gain over the no-push run, and define ties.

2. **[BLOCKING] Top-token accuracy does not establish that the score effects add.** Predictions 119.1–119.2 and the headline rule use only whether the additive vector’s argmax matches the pair’s sampled token. The pair can have a large joint-minus-singles residual while retaining the same top token. The only continuous check is a correlation over the “50 highest-scoring tokens” (lines 94–96); the design does not say which run selects those tokens or set a threshold for that correlation. Either narrow the headline to “the additive top-token rule predicts well,” or preregister a direct interaction score, `L_AB - L_A - L_B + L_0`, with its token set, aggregation, scale and threshold. EPISTASIS-FRAMING.md, lines 31–37, also calls for a named scale and reporting the interaction on probability and log-odds scales.

3. **[BLOCKING] The real-pair and random-control hit rates are not like-for-like.** “Contested” positions are selected on each row’s own generated path (lines 58–65), and the summary drops rows with no contested positions. A real pair and its `A+R_B` control can therefore be scored at different answer positions, with different style words and different coverage. The design also admits that random directions match written size, not effect size (lines 92–96), while the selected neuron’s effect is large. A weak random push can look more additive simply because it changes less. Use a fixed shared prefix and mask chosen before reading the pair/control outputs, apply it to matched `A+B` and `A+R_B` rows, and report zero-contest coverage. If 119.3 is meant as equivalence, require the confidence interval for the rate difference to fit inside ±5 points; the size section names 10 points as the smallest effect worth knowing.

4. **[BLOCKING] Gate 3 can pass while the scored positions fail.** The gate accepts a 98% match over all teacher-forced positions (lines 115–117), but the additive scores are read only at contested positions. If those positions are rare, every one could mismatch while the aggregate still exceeds 98%. Check agreement on the exact contested-position mask, separately for real and control rows; withhold affected predictions if that check fails.

5. **[MINOR] Gate 2 has the needed answers for a text replay, not an exact token replay, and its pooled threshold can hide kind-specific drift.** `results/part118/answers.jsonl` has 1,878 records and exactly 39 neuron rows at alpha 0.8 for “Who are you?”, with unit metadata and an `answer` string. It has no generated token IDs. So the stated text comparison is possible, but “first 24 tokens equal” cannot be checked as original token IDs from this file. Also, 33/39 permits all six mismatches to fall in the concept subgroup while the kind predictions still pass the gate. Call this a decoded-text check, and set per-kind replay requirements or suppress claims for any subgroup that fails.

6. **[MINOR] R and flip alpha are selected first-token measures, not clean measures of concept robustness.** Every unit was selected at alpha 0.8 on this same “Who are you?” question (line 106). For any unit with a defined `p_A`, `t_A` is its generated token there at alpha 0.8, so its flip alpha is necessarily at or below 0.8; this does not force values to be near 0.8, but it caps and selects the comparison. `p_A` can be a style token, and R is answer-prefix overlap from that point. A lower flip alpha or higher R can reflect “I,” a greeting, or formatting rather than the persona. Use a held-out prompt or a preregistered persona-bearing token/span, or describe these as selected first-token and string-stability measures only. Part 92’s design, lines 48–56, also selected/classified these units using the same question battery, so the bootstrap does not generalize to unselected neurons.

7. **[BLOCKING] Prediction 119.4 has no minimum denominator.** A pair is undecided when there are equal wins or no counted single-token wins (lines 66–68), but 119.4 uses only decided slot-by-concept pairs and sets no minimum number of those 168 pairs. One decided pair won by the concept would score 100%. Set a minimum decided-pair fraction and report decided/total counts before reading this prediction. 119.8 also holds on any tiny median gap, and 119.6 has no minimum alpha gap; add practical margins or label those comparisons descriptive.

8. **[MINOR] The agreed kind groups and reader sample support only narrow claims.** Part 92b confirms 21/21 original slots remain slot, but only 8/18 original concepts remain concept; the other 10 are disputed. Thus 8 agreed concepts are a selected subset, not a representative concept sample. The 28 concept-by-concept rows in 119.9 reuse those same eight units seven times each. Seven “both” labels (the 25% threshold) could cluster around a small number of units rather than show a broad pair effect. The 40-row samples in the other classes also reuse units. Report per-unit coverage and leave-one-unit-out or unit-clustered results, and state that the study can describe these eight stable concepts, not concept neurons generally.

9. **[MINOR] A few procedure and run-accounting details need to be made explicit.** PROCEDURE.md, lines 25–26, requires the closest work in both the design and `PRIOR-ART.md`; I found the Part 119 discussion in the design but no Part 119 entry in `PRIOR-ART.md`. Lines 55–59 and 90 require reader settings, error-row handling and a pilot check of the token cap; Part 119 gives the reader names/cap but not temperature or effort, does not say how unresolved labels enter 119.9, and does not check whether 60 generated tokens are enough for labels. Add those rules. The 2,302 main-row count correctly sums the listed answer cells, but Gate 1 needs a separate zero-hook answer against the plain answer; the pilot row list includes only one plain row. Add that gate row to the pilot/cost count or identify the existing zero-hook/no-hook records it reuses.
