# Cold critique

**Code checks.** `python3 -I -B -c` with the repository inputs produced 142 rows and 852 answers: 1 unpushed, 55 pair, 33 random, 33 real-neuron control, and 20 alone. The requested pytest command passed: 11 passed in 1.30s. The row count, shared Part 117 push arithmetic, and random seeds match the design; index 0 reuses Part 112's seed and indices 1 and 2 add 1,000,000 and 2,000,000.

1. **blocker: the theme comparison is confounded by layer.** `PART117B-DESIGN.md:69-70` treats unrelated concept as a test of shared theme. Counting `results/part117/pairs.json` shows matched and unrelated concepts share a layer in only 2 of 11 pairs. In the other 9, theme, layer, and layer-specific push geometry change together. **Fix:** choose the unrelated concept in the matched concept's layer, or stratify a preregistered within-layer theme comparison; otherwise remove the causal “theme matters” reading.

2. **should-fix: random and real controls match written norm, not effective perturbation.** `part86/common86.py:122-135,182-197` scales both neuron and random pushes to the same `||Wv||`, which is a useful residual-write norm match. It does not match downstream read/behavioral effect or native activation; only three random directions and three atlas-unlisted neurons are sampled per pair. `pick117b.py:13-20` establishes only that controls are outside Part 112's 465-unit persona screen, not that they lack persona effects. **Fix:** qualify claims to these sampled directions at matched write norm, or add controls matched on measured downstream effect and label them “not in the atlas screen.”

3. **should-fix: the 15% dilution argument is unmeasured, and +0.5 is not its control.** `PART117B-DESIGN.md:71-73` assumes the pushes are orthogonal to each other and to the current residual. `write-cosines.json` measures pairwise write-vector cosines, not their projections on the tokenwise residual. The slot +0.5 condition halves the push, far more than the proposed 15% share change. **Fix:** call 15% a heuristic, measure residual norms/projections on calibration tokens, and compare to a slot-only dose matched to the resulting share.

4. **should-fix: headline rules can decide wrongly.** `score117b.py:163-168` calls the real-neuron effect distinct from random whenever random retention is merely above one third; it does not require the registered `117b.3` two-thirds retention. Also, random/control erasure rules count `shows_persona` even when those answers are incoherent (`score117b.py:128-154`); only concept rows have a coherence threshold. **Fix:** require `random_keeps` for the real-versus-random reading, make intermediate rates mixed, and gate both control readings on a registered coherence rule.

5. **should-fix: scorer fails open on missing gate/audit data.** `score117b.py:98-100` sums only available baseline labels, so missing labels count like false and can make a unit look interpretable. At `156-163`, absent `agreement.json` leaves `agreement=None` and still permits the headline, despite the 85% withdrawal rule (`PART117B-DESIGN.md:147-149`). **Fix:** mark units with incomplete baseline labels uninterpretable, and withhold the reading when the second-reader agreement is absent.

6. **should-fix: the bit-for-bit null is not tested.** The design omits it because the hook code is unchanged and compares the new zero-push row with Part 117 (`PART117B-DESIGN.md:79-81`). Both runs use the hook; neither is the plain model. The new unpushed row uses an all-zero hook (`rows117b.py:116-121`). This does not satisfy `STANDARD-CONTROLS.md:11-12` or `PROCEDURE.md:34-36`. **Fix:** compare the hook-installed zero row against a no-hook plain run before interpreting effects.

7. **minor: the batch-composition claim is false, and the optimization inherits batch size.** `PART117B-DESIGN.md:104-107` says batch 64 matches Part 117's composition. Shared cells stay in the same batch number, but their companions differ; for example, p06 `c-1,s+1` is row 62 with Part 117 companions and row 58 with 117b's new controls. Prompts are the same, so prompt padding matches. Procedure §4 also asks for timing multiple batch sizes on real rows, while the estimate reuses Part 117's measurement. **Fix:** say only batch size is held constant, preserve/replay exact companions if output comparability matters, and time 2-3 sizes on a short 117b sample.

8. **minor: `qwen` is only a substring, not a self-claim.** Predictions 117b.4/.5 use case-insensitive substring search (`score117b.py:94-96`); a mention of Qwen counts even if the answer does not identify itself as Qwen. The design acknowledges this limit at `PART117B-DESIGN.md:157-158`. **Fix:** keep it explicitly lexical, or use the already requested `self_claim` label for a naming claim.
