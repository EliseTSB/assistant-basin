# Part 198 build notes

- The output streams are out/armA-<method>.jsonl, out/armA-mass-<method>.jsonl, out/armB-wsp.jsonl, out/armB-seq-wsp.jsonl, and out/armC.jsonl (runner subcommands; design Optimization, lines 340–357, and Reading rules, lines 397–410). Each invocation writes a start/restart record; errors are JSONL failure records. Registered records resume by frozen case, batch, or model key. Smoke (--limit) rows are marked separately, excluded from scoring, and do not suppress registered work.
- Each mass edit is one JSONL row for the atomic ten-fact batch, with ten nested before/after/took/name records, the 8-of-10 gate, matrix statistics, localization, and restoration (design Arm A “Mass edits,” lines 126–130). This gives the batch-level denominator while retaining per-fact counts.
- Arm A computes the 48 GPT-2 XL base matrices once per invocation and persists their F1, F2, PCS, and token-reading pairs in out/base-gpt2.json (design Method, lines 55–75; Arm A, lines 103–130). GPT-2 Conv1D matrices are transposed to [out, in]. The two frozen first-token IDs are used for names. already_satisfied is new > old before; took requires old > new before and new > old after, with strict comparisons as in Arm A, lines 118–123.
- Edited matrices report F1/F2/PCS/T_max/T_word localization, base T_word/rank/name diagnostics, update spectral and Frobenius norms, ratio to base sigma1, and update top-direction naming (design Method, lines 75–100; Arm A, lines 121–130). Numerical rank uses PyTorch matrix_rank's default tolerance on the float64 update because the design requests a numerical rank without naming a cutoff.
- The ROME positive control uses the first right singular vector and spectral norm of that record's layer-17 update. Its output vector is the unit-normalized `gamma * (E[target] - mean(E[target]))`; the edited suspect is the base layer plus that rank-one update. It is named at the known layer and localized against all base layers (design Controls, lines 172–185; pilot recipe pilot/explore_posctl.py).
- The first successful Arm A update is stored as a float32 sidecar inside out/; after all 24 registered cases, the process replays that first case, checks the design's strict 1e-6 * largest update entry tolerance, and restores the base again (design Arm A “Restoration and editor state,” lines 123–125). A missing reference is a failed verification, never an assumed pass.
- Arm B uses the frozen question table verbatim (design Arm B, lines 132–159). Before- and after-write exactness are runner-measured stripped-string equality across taught questions; WSP's token-level `free_exact` is stored beside the measured count and disagreements are flagged. The held-out question is reported. WSP's protection-cache home is redirected under the selected output directory.
- The matched random control uses float64 SVD and reduced QR factors from one CPU generator seeded 198 + case_id, advanced in sorted layer order. It preserves each of the five layers' singular values and replaces both singular-vector bases (design Controls, lines 174–180). The WSP sequence replays existing registered writes into a fresh process so a resume reconstructs accumulated state before continuing.
- Arm C resolves cached Hub refs/main locally, or requires exactly one local snapshot when that ref is absent. It uses stored dtype for the eight descriptive models and float32 for the two development hosts; GPT-2 c_proj is transposed, GPT-NeoX uses dense_4h_to_h, and Llama-family uses down_proj (design Method and Arm C, lines 55–57, 160–170; brief data-path instruction). The manifest hashes model config and tokenizer assets as well as model weight files. It writes T* after all three calibration maxima and before evaluation/host work. F1 per-layer robust z uses the same median/MAD scale as stats198.robust_z_of_max; the helper's model-wide maximum is also recorded. The largest/second sigma1 value is the ratio of the top two layer F1 values.
- The scorer uses two-sided exact Clopper-Pearson intervals by binomial-tail inversion, plus exact two-sided McNemar for paired random-control localization (design Size, lines 335–344). It reports 198.2 and 198.5 as descriptive values without verdicts and omits withdrawn 198.9–198.11 (Predictions, lines 372–388; Reading rules, lines 397–410).
- Before any model or edit is loaded, a normal runner command executes the inert fixtures and synthetic tests and requires the model-based crosscheck198.json gate artifact to exist with no failures and a matching `stats198.py` SHA256 (design Controls, lines 185–190). `crosscheck198.py` records this hash. This worker did not run the crosscheck because the assignment prohibits model loads. Scoring checks the saved gate, all required take counts, restorations, and the first-update state check before giving forecast verdicts.

## Ambiguities and limits

- A mass edit is ten case facts but one atomic editor call. The runner publishes one row per batch with all ten per-fact results nested. This follows the design's batch gate and the brief's request for per-record details; an alternate one-row-per-fact encoding would duplicate batch-level status.
- Controls specifies a seed of 198 + case ID but not whether the seed is restarted per layer or advanced once across all five layers. The runner uses one generator per write and advances it over sorted layers, so every control is deterministic from the stated write seed.
- Numerical rank has no frozen cutoff in the design; the implementation uses PyTorch's default float64 matrix-rank tolerance.
- Arm C lists model names but no immutable revision hashes. This follows the brief's instruction to resolve the offline cached snapshot: use refs/main when available, and otherwise refuse if more than one local snapshot exists. The selected snapshot path is recorded in every model result and the manifest. Arm C rows also store the reviewer maxima and their disclosed top tokens where the design supplies them, and the difference from those rounded references.
- EasyEdit's local mounted directory has no Git metadata (git rev-parse returned “not a git repository”), so the local HEAD could not be checked. The manifest records the required commit string and hashes the consumed ROME/MEMIT/AlphaEdit Python source files and three configs instead of inferring a commit.
- The direct design phrase “every subcommand ... one JSON line per record” does not define a JSONL identity for manifest; this implementation writes its requested structured artifact as out/manifest.json.
